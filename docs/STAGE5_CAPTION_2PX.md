# 场景 5 介绍文字下移 2px 的可行性分析

> 结论：**不可行，已回退。** 文字保持页面 y36-47（底边 47），与日版原文一致。
> 本文记录全部排查过程与实测数据，供以后复用。

## 背景

场景 5 介绍的「帝帝帝山」在页面 y36-47。曾尝试把它下移到 y38-49（设计位置），
要求：

1. 静止期（SCY=0）文字显示在屏幕 y38-49；
2. 停顿期（SCY=48）文字不得露出；
3. **卷轴轨迹不变**（SCY 逐帧与改动前完全一致）。

第 1 条要求文字底边 = 49，第 2 条要求文字底边 < 48。**两条互斥。**

## 一、几何约束 【静态确认】

```text
静止期 SCY=0  → 屏幕显示页面 y ∈ [0, 143]
停顿期 SCY=48 → 屏幕显示页面 y ∈ [48, 191]
```

文字底边在页面 y49 时，停顿期屏幕位置 = 49 − 48 = **+1**，即顶部露出 2 行。
要让它在停顿期不可见，底边必须 < 48，即 ≤ 47。

**因此在「卷轴不变」的约束下，文字底边 ≤ 47 是唯一可行解。**

## 二、三条路线的实测结果

### A. 数据层 【静态确认】

| 方案 | 不可行原因 |
| --- | --- |
| 精灵遮盖 | 精灵不随 SCY 滚动，会脱离背景运动 |
| 窗口层遮盖 | 窗口只能从 WY 往下铺满全宽，无法只覆盖 2 行 |
| 调色板 | BGP 无法只隐藏特定颜色 |

### B. VBlank 代码补丁 【实测】

把 `$1DFB`（应用 LCDC/SCX/SCY/BGP）原样搬到别处、ISR 的 call 次数不变，
只在中间插 `nop`，然后跑完结局序列逐帧对比 credits：

| 额外周期 | credits 差异帧数 |
| ---: | ---: |
| **+0** | **0** |
| +8 | 7 |
| +16 | 12 |
| +24 | 4 |
| +40（多一次 call/ret） | 6 |

**credits 的滚动对 VBlank 周期精确到 8 个周期。** 而露头判据最少需要
`cp`(8) + 分支(8-12) = 16-20 周期，因此任何挂在 ISR 路径上的补丁都必然
让 credits 的滚动文字产生 1px 闪烁。

> 已排除数据损坏：单独把候选代码洞 `$6760-$677F` 清零，结局序列 **0 差异**，
> 说明差异确实来自周期开销而非数据占用。

### C. 改卷轴到 SCY=50 【实测】

停顿位置上移 2px 后，顶部露头消失，但停顿窗口从 `[48,191]` 变成 `[50,193]`，
**页面 y192-193 的山尖会提前露出**。实测截图确认。

只有把整页内容再下移 2px 才能同时保住顶部和底部，但那样整段开场动画的场景
都会偏移 2px——同样不可接受。

## 三、逆向过程中确认的事实

### credits 数据布局 【实测】

| bank 6 CPU 范围 | 内容 |
| --- | --- |
| `$5E7A-$6279` | credits BG map（1024 B），装载后拷贝到 VRAM `$9C00` |
| `$62C4-$6368` | credits 文本表。**其中的 `FF` 不是填充，是空行分隔** |
| `$6760-$677F`、`$67A0-$67BF` | 实测空闲（清零后结局 0 差异）|

教训：早期把补丁放在 `$5EA9`（credits map 内）和 `$62F3`（文本表内），
分别造成 credits 画面花屏和 `LICENSED TO` 后面出现乱码。腐蚀测试只覆盖了
15 个可捕获画面，**没有覆盖 credits**，因此当时没发现。

### VBlank ISR 结构 【实测，bank 0】

```text
$1D16  ISR 入口
$1D22  检查 $FF91 bit2 —— 队列非空则跳 $1DA4
$1D2A  inc 帧计数器 $D032 / $D034 / $D035
$1D36  call $1FB2 / $1EE3 / $1E2E
$1D3F  call $FF80      ; OAM DMA
$1D48  call $1DFB      ; 应用 LCDC/SCX/SCY/BGP
$1DA4  处理 $CB00 队列：3 字节条目 [addr_lo, addr_hi, value]，以 0 结尾
```

**走队列分支会跳过 `$1D36-$1D48`**（含帧计数器、OAM DMA、LCDC 更新），
所以队列不能每帧使用，否则帧计数器冻结、开场停顿永不结束。

### 开场滚动引擎位置 【实测，未定位成功】

- bank 5 `$428C` 与 bank 1 `$4897` 各有一份 `push bc; ld a,[$D3BA]` 的引擎，
  **运行时不执行**（对 bank 5 `$4200-$42FF` 全地址下钩子，0 次命中）。
- `$D055`（SCY 影子）每帧由间接寻址更新，无法用字节模式定位。
- PyBoy 没有内存写钩子；在 ISR 入口读栈顶返回地址，显示主循环 593/613 帧
  都停在 `$1DC9-$1DCB` 的 VBlank 等待自旋，拿不到真正干活的代码位置。

## 四、唯一未走通的方向

把钩子挂到**只在 S5 开场执行、结局不执行**的代码上（这样加周期不影响 credits），
并通过 `$CB00` 队列做一次性 VRAM 写入。

前提是找到那个每帧更新 `$D055` 的间接写入点，需要**单指令级追踪工具**
（PyBoy 只支持 frame 级 tick）。

## 五、当前决定

回退到 v0.5.3 状态：

- 文字保持页面 y36-47，底边 47 —— **与日版原文一致**
- 露头：无（47 < 48）
- credits：完好（零补丁、零周期开销）
- 底部构图：不变

2px 在 160×144 的 GB 屏幕上约等于 1/4 个字符高度，实际观感差异极小。
