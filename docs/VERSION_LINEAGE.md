# 版本谱系与并行编号

本仓库和原开发工作区各自演进，**v0.5.2 在两处指不同的东西**。这份文档把两条
线固定下来，避免以后查历史时混淆。

## 两条独立的分支

```text

    → v0.5.3_heading      f58da5e0…   配置页标签收紧、体力槽下移 2px
    → v0.5.4_credits      07cf119b…   原版演职人员表后追加署名卡
    → v0.5.5_staff        b3591397…   演职人员表原生重写（32 条中文 + 双缓冲流）

  v0.5.1_stage5_up2      f96fe0ec…
    → v0.5.2              959835314b68… 删除 6 次死装载（纯性能，无内容变化）
```

卡带不同（美版 vs 日版 Rev1），卡带头、资源布局、版权行数都不同。

## 为什么不合并

已用实机截图核对：两边标题页虽然都写「星之卡比」，但**样式完全不同**。

| 维度 | 开发工作区（美版基准） | 本仓库（日版基准） |
| --- | --- | --- |
| Logo 字形 | 横排扁平贴纸风 | 斜排手绘风 |
| Logo 占位 | y=6–84 | y=0–95 |
| 背景 | 纯白 | 云朵 / 草地 / 城堡 |
| 版权行 | 2 行，从 y=121 | 3 行，从 y=100 |
| 深色像素 | 3,081 | 3,884 |

把美版基准的中文 Logo 贴到日版基准的云朵背景上会直接冲突。因此**美术资源不可
互换**。

可以复用的是和画面基准无关的部分：v0.5.5 的「演职人员表双缓冲 VBlank 流」是纯
代码方案，32 条中文译文也与基准无关。要做这两项，应当**在日版基准上重新实现**
并重新出图，而不是搬 ROM。

## 怎么判断手上是哪个

```bash
# 卡带头标题（0x134 起 16 字节）
xxd -s 0x134 -l 16 KirbyDreamLand_CHS-Monado.gb
# 本仓库应为 HOSHINOKA-BI；原开发工作区为 KIRBY DREAM LAND

# 整 ROM 指纹
sha256sum KirbyDreamLand_CHS-Monado.gb
```
